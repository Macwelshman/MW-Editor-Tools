# Security, stability and release review — 0.4.218

Reviewed 2026-10-23 at the user's request before wider distribution. This is a source/dependency/regression review, not a security certification or a guarantee against every asset/mod combination. No publishing, game-file modification or computer use.

## Assessment

VERIFIED-STATIC: no outbound network clients, shell/process execution, native interop imports, dynamic JavaScript evaluation or raw HTML insertion found in runtime source (`src`, `UI/src`). Runtime file access found is local settings/window persistence; Multi-Save delegates asset saving to the native editor. No arbitrary external clipboard file import or user-selected assembly loading found in runtime code. Test-only assembly resolution and installer process inspection are separate from the shipped mod.

VERIFIED-STATIC: pack JSON uses `TypeNameHandling.None`, bounded depth and request length. Selective field parsing rejects duplicate properties/indices, invalid names/types and oversized arrays. Asset selection/revision tokens, exact component identities, read-only validation and fingerprints guard writes. Transfer snapshots reject unsupported runtime objects, bound depth/collection size, detach mutable values and validate prefab references. React renders text as text. These checks reduce exposure from malformed data; they do not sandbox another installed mod.

VERIFIED-STATIC: recovery retains its existing source, ownership, geometry, typed companion data, mapped reference, ambiguity and deferred native completion checks. The review does not weaken those checks or rewrite accepted restoration paths. Save callbacks use generation invalidation; lifecycle cleanup releases modules independently so one cleanup error does not suppress the rest. No new runtime hooks/systems/UI added.

VERIFIED-STATIC: installer payload names are allow-listed and hash-checked; destination is restricted to a Mods/MWEditorTools path; game-installation and reparse-point paths are refused; previous files are backed up/verified, writes are locked and failures attempt rollback while the game is closed. Hash verification detects corruption; it does not authenticate a modified installer from an untrusted distributor. Installer tests use disposable folders and the existing 0.4.180 embedded payload, not a new 0.4.218 release package.

## Issues corrected

1. **Build dependency advisories:** webpack 5.97.1 had two low-severity `experiments.buildHttp` advisories. This project does not enable that feature and webpack is a development dependency, not a shipped runtime library. Updated exactly to patched 5.104.1 and refreshed the lockfile with install scripts disabled. Primary advisories: [userinfo allow-list bypass](https://github.com/webpack/webpack/security/advisories/GHSA-8fgc-7cc6-rx7x), [redirect allow-list bypass](https://github.com/webpack/webpack/security/advisories/GHSA-38r7-794h-5758).
2. **Unnecessary editor startup work/log volume:** the read-only nested/companion definition inventory scans thousands of definitions and logs their names in one editor tick. It is now disabled by default. For deliberate troubleshooting only, set process environment variable `MW_EDITOR_TOOLS_DIAGNOSTICS=1` before launching the game. Normal Undo success/failure diagnostics remain enabled. Recovery does not depend on the inventory.
3. **Repeated regex construction:** priority sorting previously constructed the same regex for every asset (up to 1,000). It now constructs one per preview and reuses it, preserving the 100 ms match timeout, overall budget, 500-character pattern limit, opt-in behavior, ordering and validation. This removes repeated parsing/allocation; no frame-rate or real-world timing improvement is claimed without profiling.

## Remaining distribution gates

- **Newly observed runtime blocker:** the subsequent 0.4.218 native run fails bike-rack move capture/Undo and then ordinary-prop capture on the retained rack's source association. This supersedes readiness assumptions for that scenario. Exact cause is under investigation with 0.4.219 diagnostics; see [scope and evidence](BIKE_RACK_DIAGNOSTIC_0.4.219.md). Colour/priority/component save/reopen is user-confirmed and need not be repeated.
- **Packaging is stale:** InstallerCore/Setup/BuildInstaller/VerifyRelease still intentionally describe 0.4.180, with its PDF/release notes/payload. They must be versioned together and the actual new EXE/ZIP/manual verified before distributing current code. Do not relabel the old package as current. README and TEST_PLAN now distinguish the latest review from the last packaged release.
- **Native persistence/combined acceptance:** 0.4.217 has user acceptance for first/repeated bike-rack and both marker move Undo, with nine complete source/graph/companion checks. That session contains no new deletion or save/reopen run. Check a disposable mixed asset through supported delete/move/Undo, component/localisation/priority editing, Colours and Multi-Save, then save/reopen and compare data/references. Confirm normal startup without the optional inventory in 0.4.218.
- **Compatibility:** private editor APIs and game assembly identity checks restrict what is verified. Recovery/localisation/heading/workspace paths include explicit build guards; not every module uses one shared build gate. Revalidate supported game builds and interactions with other mods. This review does not establish safety on an unknown future game build.
- **Public source hygiene:** the working tree contains extensive earlier uncommitted development. Create a coherent reviewed release commit before distributing source. Local evidence contains asset names, local usernames/paths and proprietary assembly identities; exclude private logs/evidence from a public source export or sanitize deliberately. The focused secret scan covers current source/installer files only, not full Git history. Choose redistribution/source licensing terms before an open-source release; no licence was invented here.
- **Maintainability:** several recovery and pack files use dense one-line methods and partial-class state shared across files. Broader formatting/state-machine refactoring would improve readability, but is deferred to avoid mixing a large behavioral rewrite into accepted Undo fixes. Existing pure-policy tests are the appropriate boundary for future incremental extraction. No measured memory/frame-time profile or long stress session was performed.
