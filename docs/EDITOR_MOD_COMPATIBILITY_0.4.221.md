## Important compatibility gaps in MW Editor Tools

1. **Broad refusal and startup coupling.** `ComponentConfirmation.Initialize` requires actual loaded Harmony2.4.2.0 and refuses any existing patch on `InspectorPanelSystem.RemoveComponent`. `Mod.OnLoad` invokes this before the isolated optional-module blocks. Its failure reaches outer catch/OnDispose, so the whole mod can be unavailable, not just confirmation. This is an existing behavior, not a currently observed conflict. An older Harmony *reference* in another DLL does not prove an older runtime is loaded; the present log confirms2.4.2.0.
2. **Shared core hooks and load order.** `BulldozerTrace.Patch` refuses foreign owners when attaching `BulldozeToolSystem.Apply/GetAllowApply`, `ApplyPrefabsSystem.OnUpdate`, `PrefabSystem.OnUpdate`, `ReplacePrefab/Finalize`, `PreCullingSystem.OnUpdate` and native move hooks. A main Attach conflict rolls back its hooks and loses bulldozer/native Undo; local object/area move attachment exceptions can disable those subpaths separately. A mod patching the same method *after* this check is not automatically re-audited by the Undo hook layer. Component removal/list interception does have additional execution-time ownership checks. Therefore no blanket load-order-independent conflict protection can be claimed.
3. **Shared input, not shared history.** The recovery shortcut polls Keyboard.current; own shortcut conflicts are checked, not every other mod's shortcuts. Default MW Undo is Ctrl+Z; browser category shortcuts are disabled by default and use Alt combinations when enabled. Find It's [official listing](https://mods.paradoxplaza.com/mods/77240/Windows) documents Ctrl+F/P/R, so no identical default key combination was identified there. Rebindings or another active editor Undo require a combined test or distinct bindings.
4. **External edits and custom tools.** Exact source/identity/typed companion/reference checks intentionally refuse an Undo after intervening changes. A mod changing tree state, placement, prefab components or regenerated lanes may therefore make a previous action unavailable. Custom deletion/move tools must not be advertised as covered merely because they resemble native tools. There is no evidence linking the earlier intermittent bike-rack failure to another mod.
5. **UI composition.** Current wrappers preserve Original and most props; this is friendlier than replacing native UI. It still depends on private module names, heading paths, hierarchy layout and focus behavior. Another wrapper/overhaul can change those contracts. Launcher neighbor avoidance and native focus checks are managed-tested, not a guarantee for arbitrary mod UIs.

## Recommended release position

Describe current Find It/icon-library/environment combination as **co-loading observed**, and cached tool-mod comparisons as **no exact hook overlap identified in inspected versions**. Do not publish a universal compatible claim or claim MW Undo covers another mod's custom operations. Document the standalone Component Tool exclusion.

Before claiming wider support, test one target mod at a time on disposable assets in both effective load orders: load editor, inspect component headings/Workspace Save All, native prop/marker/rack move and deletion Undo, save/reopen, then the other mod's own tool and a subsequent supported MW native action. Include editor exit/re-entry, Ctrl+Z ownership and a separate save/edit in each module. No need to alter the user's current playset to complete this static review.

Most useful follow-up implementation: report conflicting patch owner/method/version clearly, isolate unavailable optional features from whole-mod startup, and address late-patch detection before approving operations. Keep conservative source/reference safeguards; do not simply whitelist an unknown patch to suppress warnings. Such runtime changes were not made in this review.
