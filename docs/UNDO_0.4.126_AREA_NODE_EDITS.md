# Undo 0.4.126 — node additions, same-node moves and deletions

User explicitly authorised adding surface/area nodes, moving added nodes and deleting nodes on 2026-10-17. Clarification: addition and subsequent moves of that same added node must be one Undo action, restricted to that node. This is an extension to the 0.4.125 stage already user-accepted including persistence; it requires new native acceptance.

VERIFIED-STATIC implementation: supported bound and unbound Surface/Space polygons now permit exactly one uniquely identifiable ordered node insertion or removal while retaining at least three nodes. Retained vertices preserve world position/elevation and attachments; polygon flags, prefab, ownership, container, navigation and other metadata remain guarded. Changed counts greater than one, ambiguous duplicate matches, merged/multiple polygons, whole-polygon node-tool deletion and unsupported attachment transitions remain refused. Native-added standalone cache must agree with world geometry. Existing ordinary moves and observed bound -1/0 surface snapping retain their accepted checks.

Default Cancel captures the original before entering Remove; Remove Cancel completion observes the actual scoped native GetAllowApply and resulting ApplyMode.Apply. Create/Modify cancellations do not commit an entry. Nested Cancel cleanup during Apply cannot replace the outer observation. Preview cancellation and denial preserve the previous slot; accepted uncaptured edits clear stale recovery rather than altering native execution. The existing single-original temporary-polygon check rejects whole-area deletion and unproved sibling changes.

A later move combines only when the target/live identity and owner agree, the move's exact before-image and generated graph match the addition's after-image, and only the added node changes position/elevation or its supported attachment. The combined entry retains the original pre-addition geometry/source and the final after-image. Successive moves of that node remain combined; moving another node, adding/deleting another node or any intervening source/companion change starts a separate action. No-op/cancel does not replace the slot. Combination failure falls back to a separate supported edit without changing native behavior. No history/Redo added.

Surface expansion counts can follow a topology edit because the inspected Expand payload contains only offset values; complete finite before/after arrays are captured and the exact before-array is restored. UNPROVEN grouped native acceptance on disposable assets, bound and unbound surface/area:
- Add one node, then Ctrl+Z: added node disappears.
- Add one node, move that same node (optionally move it again), Ctrl+Z once: the addition disappears entirely.
- Add one node, move a different existing node, Ctrl+Z once: only the different node returns; the addition remains.
- Delete one node from a polygon with at least four nodes, Ctrl+Z: the deleted node and geometry return.
- Cancel an addition/removal preview after an accepted action: prior Undo remains usable.
- After accepted edits/Undo, save a new disposable restored copy and reopen; original assets are never overwritten.

Keep the tool active after releasing input. Stop after recovery errors and reload without saving. Prior 0.4.125 acceptance remains recorded separately. Network moves and third-party tools remain unsupported. No computer use, game-file modification or publishing.
