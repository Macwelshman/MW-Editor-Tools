# Development plan

1. Phase 1: completed static investigation/scaffold; document runtime gaps. Compare official installed template with provisional net48 target after installation. No deployment.
2. Phase 2: one component-header confirmation experiment; prove cancel, confirm, dependency cascade and stale dialog behavior. No undo claims.
3. Phase 3: prove one Object list capture/restore, then Effect, Area and Net separately. Validate save/reopen for each. Bulldozer remains disabled until precommit graph/order proof.
4. Phase 4: shared selection, capabilities, history, settings and persistent window; module isolation and shortcut conflict checks.
5. Phase 5: Prop Replacer normal, rapid, multi-replace and undo; exact probability and pivot tests.
6. Phase 6: migrate existing Component Manager, Colour Variation and Multi-Save incrementally without overwriting originals.
7. Phase 7: compatibility, persistence, failure recovery and release packaging.

Each phase ends with evidence and explicitly supported operations. No progression into runtime implementation from toolchain installation alone.
