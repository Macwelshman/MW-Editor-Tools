# 0.4.97 native capture correction

VERIFIED-RUNTIME: 0.4.96 log on 2026-10-13 shows no completed area/bound-prop capture. Repeated area attempts report "The method or operation is not implemented." Inspector root is usually none after switching tools. The logged standalone DeckChair01 attempt is independently refused for Game.Objects.SpawnLocation and has activity-location children; it is not a supported simple standalone prop.

VERIFIED-STATIC defect: eight production call sites boxed DynamicBuffer<T> or NativeList<T> and called Enumerable.ToArray. Both installed types' generic and non-generic IEnumerable.GetEnumerator explicitly throw NotImplementedException at IL_0000/IL_0005. Public direct enumerators are implemented. Native identities: Unity.Entities 0.0.0.0 MVID 3d6b23ae-b281-44a6-a5f4-cbd5fd3d75e6; Unity.Collections 0.0.0.0 MVID f4ddbc30-cb47-4061-9107-4a184ca0481e. Evidence: docs/evidence/undo-0.4.96-native-enumeration.txt and undo-0.4.96-compiled-native-boxing.txt. The compiled module shows CaptureAreas calls at IL_0167/016c and IL_017d/0182, EnableAutomaticBoundProps IL_008a/008f, and five CaptureAreaNetwork sites. HYPOTHESIS strongly supported by the exact throw behavior and matching logged exception: these caused the area capture failures. The old log omitted exception stacks, so it does not independently identify the throwing call.

Correction: use DynamicBuffer.AsNativeArray().ToArray and NativeList.AsArray().ToArray, calling the supported NativeArray copy API without interface enumeration. Only detached managed arrays are retained; native views do not escape. The new Phase3 native collection audit reads the installed collection method bodies and the actual built mod IL, refusing native collection boxing into LINQ. This addresses a gap in the prior managed/stub checks.

VERIFIED-STATIC second defect: automatic bound capture depended on context.Asset/CanArm, which require an enabled inspector, and attempted to resolve a nested target using a helper that refused nested roots until already armed. Correction: resolve the native owner before adoption, permit nested-root discovery only for the read-only preflight, adopt against that explicit writable owner and scope root/forest searches to its entity. A different nonempty inspector asset, unsupported graph, readonly owner, missing references and existing budgets still refuse capture. Each new deletion revalidates adoption; stale armed context cannot skip automatic setup for a different owning asset. No live cache or preparation edit is introduced.

Area mode/context and standalone unsupported-schema refusals are now visible in status. Unexpected capture exceptions include full stacks in the log. DeckChair01/activity-location schemas remain excluded; no whitelist entry was added merely to bypass the refusal.
