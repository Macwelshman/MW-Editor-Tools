# Filtered targeting and Undo feedback — 0.4.224

User-authorised IMPLEMENT scope: filtered targeting, highlighted selection and clear Undo eligibility feedback; preserve companion data/references and accepted Undo. No publishing, third-party/game file edits or computer use.

## User workflow

In **Replacer**, choose **Target elements** after selecting an editable asset in Object Info and returning to native Select. A single Target type dropdown offers All supported types, Props, Trees and plants, Effects, Markers, Surfaces, Spaces, Networks and Lanes. The owning asset remains inspected. Gold marks the hovered element; clicking selects it for MW copy/replace and marks it cyan. Clear selection drops only that target. Stop targeting or Escape returns to native Select. The existing Copy, Replace and Replace all buttons use the target while this mode is active; Ctrl+C/Ctrl+V/Ctrl+Shift+V use the same existing guarded viewport path.

This is a single MW clipboard selection and an eligibility preview. It does not select another prefab in Object Info or replace native move/bulldozer workflows. Return to native Select and use the existing native tool for moving/deleting. No multi-selection, action history, group deletion or new Undo category is introduced.

Undo feedback is conditional and explicit. Hover identifies a candidate without constructing a full snapshot. Clicking runs a detached read-only preflight once for the selected target. It reports data readiness, unsettled data, read-only/other-asset ownership, unsupported additional components (including Anarchy protection), unavailable hooks, network move exclusion or standalone network exclusion as appropriate. Data preflight success is not a promise that a later action will be recorded: native capture repeats its source, companion, reference and completion checks. Clicking the same target again refreshes the preflight.

## Safety and implementation

VERIFIED-STATIC: a separate `EditorTargetingTool : ToolBaseSystem` owns only its own active-mode raycast masks/input and render overlays. There are no new Harmony patches, whitelist additions, asset/ECS component writes, prefab refreshes, dirty flags or native Inspector/ToolSystem.selected writes in the targeting path. The existing native selection, deletion, move and restoration algorithms remain in place. Targeting refuses activation over another active custom/move/placement tool and pauses during dialogs, saving or recovery.

Native raycast masks separate static objects, areas, networks and lanes; fine classification checks the actual hit entity. Buildings/upgrades and other unsupported categories are excluded. Props/plants/effects/markers share the native static-object raycast category: an excluded nearest static hit is refused with feedback; the tool does not promise click-through selection behind overlapping objects of that same broad category. Area masks distinguish surfaces/spaces. Markers and editor containers are included through native flags. Native UI/camera/tool blocking bits are retained and checked before selecting, preventing clicks through MW controls.

The selected entity includes its version and is revalidated before clipboard dispatch. Selection expires on filter/asset changes, leaving the mode, unavailable entities or invalid ownership. Cyclic/deep/non-unique owner links are refused. Read-only referenced prop/effect prefabs remain selectable within an editable owning asset; their data is never edited. A stale explicit selection does not silently fall back to a different hover target. Current selected and hovered entities are distinguished even when their prefab names match.

Viewport Copy/Replace uses a narrow target-source interface while this tool is active. Existing unique native placement-to-source-row mapping, exact ownership, replacement type/settings preservation, foliage completion and replacement Undo remain authoritative. A stale browser-hover sample cannot override an explicit MW target. Ordinary native/browser clipboard paths retain their previous behaviour outside this mode. Old UI commands cannot fall back to a row after targeting has stopped.

Highlights are render-buffer data only: transparent-fill rings for objects/markers/effects; curves for networks/lanes; polygon outlines for areas. Non-finite geometry is skipped. Area outlines use a maximum256 segments (sampling polygons up to the existing4096-node preflight limit), avoiding a large per-frame overlay allocation. Full companion/source snapshot preflight runs only on a new explicit click, not each hover frame. The preflight retains no new Undo entry and does not call Begin/Invalidate/Prepare/Restore. Existing snapshot budgets and unsupported-data refusals remain enforced.
